# 店家照片：實作範圍與待驗證項目

更新：2026-09-19。需求是讓使用者看到評論中的食物照片，再決定是否用餐。

## 2026-09-19 節省 API 費用與體驗調整

- **搜尋才是主要成本。** 依 Google 公布價目，Nearby Search Enterprise 每千次 $35（每月免費 1,000 次），Place Details Enterprise $20，Place Photos 每千次 $7。一次首頁約為搜尋＋1 張照片，因此減少「不必要的搜尋」比省照片有效。費用請以 [官方價目](https://developers.google.com/maps/billing-and-pricing/pricing) 為準。
- **店家資料沒有時限，改顯示「還有多久打烊」。** 用 Google 回傳的 `nextCloseTime` 在本機倒數（每 30 秒重繪，不需新請求）；剩不到 30 分鐘以警示色顯示，過了打烊時間就視為已打烊並不再推薦。只有換餐段、隔天，或回到 App 時已移動超過 500 公尺，才重新搜尋一次，且只在使用者回來、按「再幫我挑」或點備選時觸發，不用計時器；並保留目前顯示的店家。定位失敗、回傳示範或空結果時，不會覆蓋原有的真實結果。已知取捨：長時間開著 App 時，評分與價格可能不是最新。
- **下拉刷新 90 秒內不重複搜尋。**
- **照片簽章憑證由 5 分鐘改為 30 分鐘**，且不再與店家資料綁在一起（店家資料已無時限）。在憑證期限內瀏覽不再多打一次照片清單查詢。簽章只用來防止任意代理，不是 Google 的照片效期。
- **記憶體內照片快取（不寫入磁碟）**：最多 8 張、保留 10 分鐘。換回上一張、從備選換成主推薦、開詳情或確認頁，都不再重複請求同一張照片。Google 對 Places 內容快取有限制，因此保持短時間、僅記憶體；正式上線前請再核對 [Google Maps Platform 條款](https://cloud.google.com/maps-platform/terms)。
- **自動載入延後 350 毫秒**：連續換店時，沒停留的店家不會送出照片請求。點擊、重試與快取命中不延遲。
- **圖片尺寸依用途**：縮圖 400×300、卡片與放大 1000×750（原本一律 800×600）。
- **搜尋與詳情、照片各有每日額度**，照片用完不會讓「決定這餐」失敗。
- **零額外成本的資料**：營業中顯示「幾點打烊」（`nextCloseTime`），店家類型用官方的 `primaryTypeDisplayName`（Pro 欄位；搜尋已是 Enterprise，不改變 SKU），並用官方 `types` 補強口味標籤。
- **照片失敗與重試更安靜、也更省。** 重試只重新要「圖片本身」，不再多打一次照片清單查詢；只有清單本身失敗才重查清單。憑證過期（`INVALID_PHOTO`）時，會在轉圈畫面後面自動換新憑證再試同一張，使用者看不到錯誤。失敗畫面維持相同高度，只留小圖示與一行短字，整塊都可以點擊重試；備選縮圖只顯示圖示。每日額度用完等需要說明的長訊息，放在圖片下方。無法解碼的圖片會先從記憶體丟掉再重試，避免一直拿到同一份壞資料。成功時以淡入呈現。
- **網路瞬斷自動重試一次，斷網時照片保持安靜。** 圖片請求若在 3 秒內就因網路失敗（封包遺失、連線被重設），會在轉圈畫面中靜靜重試一次；一直等到逾時才失敗的不會重複，避免使用者等兩倍時間。App 已知離線（首頁橫幅）時，不在記憶體裡的照片不再各自嘗試，只顯示一行「離線中 · 暫時看不到照片」（備選縮圖顯示「離線中」，並隱藏「查看照片」按鈕），網路恢復後自動載入。已在記憶體的照片照常顯示。
- 未做：讓 App 直連 Google 圖片 CDN。它不減少 Google 計費（`media` 呼叫仍計費），卻要處理 Web CORS 與兩套流程。

## 最新：三張照片與官方菜單入口

- 首頁自動載入主推薦第一張；App 每個店家相簿最多提供三張，第二、三張按需載入。備選／詳情仍按「查看照片」才下載。
- 後端照片清單、Flutter 解析與相簿都限制三張，並保留作者與來源。「更多照片與評論」直接開啟該店 Google Maps 頁面。
- 搜尋／詳情一併取得 `websiteUri`，不新增獨立官網查詢。官網不是菜單：只有人工確認的官方餐點頁顯示「看菜單」，其餘顯示「店家官網」，都沒有則在詳情提示尚無已確認菜單連結。
- 人工菜單對照維護於 `server/menu-links.mjs`，依精確 place ID 配對、90 天後需重新確認。首批涵蓋 IKEA 桃園店／瑞典餐廳與麥當勞大園高鐵南餐廳；不代表其他店家也有菜單。
- 確認來源：[IKEA 桃園店官方餐點頁](https://www.ikea.com.tw/zh/store/tao-yuan/ikea-food-and-beverage)、[麥當勞台灣官方菜單](https://www.mcdonalds.com/tw/zh-tw/full-menu.html)。僅提供外部連結，未複製官方圖片或宣稱各分店品項一致。
- Google 照片仍沒有食物限定分類。商家授權照片／菜單上傳系統屬未來功能，本轮未實作。
- 115 項 Flutter／17 項後端測試通過，靜態分析正常；涵蓋三張上限與按需載入、已確認菜單／一般官網區分、無效網址、開啟失敗重試與大字體。

以下為先前各輪實作紀錄；原先十張上限已由本輪三張取代。

## 2026-09-19 減少 API 請求

- 首頁只自動載入主推薦第一張照片；備選縮圖與詳情頁按「查看照片」才載入。主推薦仍可逐張瀏覽最多 10 張。
- Nearby／Details 一併取得 `photos`，回傳署名、短效簽章及到期時間；Flutter 直接使用這次回應，不另查清單。空照片清單也不重查；過期或接近到期時取得新清單，手動重試同樣重新取清單。
- 詳情沿用當前有效店家資訊，過期才更新；照片載入中阻擋重複點擊。
- 該輪未新增快取；現已改為短時間記憶體快取，見上方最新說明。照片資料不進 JSON／收藏／歷史。Google 限制照片名稱快取，簽章期限不是快取授權。[照片規則](https://developers.google.com/maps/documentation/places/web-service/place-photos)
- `photos` 在 Nearby 屬 Pro，原搜尋因評分／價格已使用 Enterprise，新增欄位不提高現有搜尋 SKU。減少請求數不等於同比例省費。[欄位與 SKU](https://developers.google.com/maps/documentation/places/web-service/data-fields)
- 全新首頁、三家都有照片、無重試：原搜尋 1＋清單 3＋照片 3＝7 次；改後搜尋 1＋主照片 1＝2 次 Google API。照片用量從 3 降為 1，費用仍依 SKU、免費額度與操作量。
- 110 項 Flutter／15 項後端測試通過，靜態分析無問題；涵蓋請求計數、按需載入、連點防重複、過期更新、署名與不持久保存。
- 桃園高鐵站模擬器用量差分實測：首次首頁 nearby=1、photo=1、photo_list=0、details=0；開詳情計數不變，點 IKEA 備選照片才新增 photo=1。

## 官方資料能提供什麼

Google Places 的 `Review` 沒有附圖欄位，`Photo` 也沒有食物／環境分類或關聯 review ID。因此目前無法僅用官方欄位保證「這是某則評論的食物照片」，也不能把作者頭像 `photoUri` 當成餐點照片。[Review／Photo 結構](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places#Review)

Place Photos 提供同一家店的照片，可能來自店家或使用者，包含餐點、菜單與環境。這輪實作以「店家照片」標示，保留多張瀏覽與來源連結，沒有宣稱已完成食物篩選。[Place Photos 官方文件](https://developers.google.com/maps/documentation/places/web-service/place-photos)

## 本輪完成

- 決策卡及位置詳情可以顯示照片，單次最多接收官方回傳的 10 張，上一張／下一張按需載入。
- 只為當前顯示的店家查照片，不為附近所有候選抓圖；每張請求限制為 800×600 以內。
- 保留所有攝影者名稱與可用作者連結、Google Maps 歸因、照片來源及回報連結。
- Photo ID、照片網址與圖片不寫入 `shared_preferences`、收藏或歷史；畫面切換時釋放舊圖。
- App 只向 EatSet 後端查照片；後端用 30 分鐘簽章憑證限制圖片請求，固定 CDN 白名單與尺寸。Google 金鑰只在伺服器，圖片 CDN 請求不帶金鑰。
- 無照片、未連線、照片過期／配額／網路錯誤、圖片解碼失敗都有明確狀態。重試會重新取得照片清單，避免一直使用過期的資源名稱。
- 切換餐廳會丟棄上一家的遲到回應，避免顯示不屬於目前店家的照片。
- Demo 不配上無關食物照片，顯示「示範店家沒有實景照片」。

## API 與最後設定順序

附近搜尋、店家詳情與照片均已遷移至後端 **Places API (New)**。App 使用 `EATSET_API_BASE_URL`，後端使用 `GOOGLE_PLACES_API_KEY`；不再把 Google 金鑰編入 Flutter。服務端已有 IP／全站每日限額與用量統計，尚未雲端部署；後續已綁定本機金鑰並完成少量真實 API 測試。詳見 [後端說明](../server/README.md) 與 [金鑰流程](places-setup.md)。

正式接線時驗證：

1. 同一家真實餐廳能由後端取得 New API 照片，既存 place ID 能正常更新。
2. 圖片 CDN、相片來源、作者與回報連結能在 iPhone／Android 開啟；網頁版另驗證跨來源存取。
3. 真實相片是否含足夠的食物內容，不能只以 mock 照片測試推論涵蓋率。
4. 依實際發行地區與資料來源完成 Google 歸因、條款與隱私檢查。[照片歸因政策](https://developers.google.com/maps/documentation/places/web-service/policies)

## 尚未完成的食物限定需求

這輪沒有抓取 Google Maps 網頁評論、沒有擷取評論附圖，也沒有 AI 判圖或「只顯示食物」模式。若需要保證食物照片，下一階段需選擇具分類與使用授權的照片來源，或建立店家／使用者上傳與審核機制，再實作食物照片優先排序；不能只把一般店家照片換個標題。

## 驗證

`test/place_photos_test.dart` 使用 mock HTTP 與測試專用單色圖片，涵蓋來源對應、作者、金鑰隔離、HTTP／內容錯誤、按需載入、換店競態、重試與大字體版面。未使用真實店家照片，未驗證真實配額與照片涵蓋率。

## 2026-09-19 真實資料測試

使用台北車站公開測試座標，本機後端成功取得店家照片清單及 JPEG；iOS 模擬器能顯示門面照、切換至餐點照，保留作者和來源。這只驗證實際照片顯示，仍未實作食物分類或評論附圖對應。

實测並修正：詳情請求指定 zh-TW，避免店名切成英文；詳情刷新完成才載入照片，同一店家的資訊更新不再重置首頁照片或重複下載。

當日本機後端的 `GOOGLE_REQUESTS_PER_DAY=20` 已用完：附近搜尋 3 次、詳情 2 次、照片清單 7 次、圖片 8 次，全部成功；之後的照片請求由本機 `DAILY_LIMIT` 阻擋。這是搜尋、資料及照片共用的測試上限，不代表 Google 免費用量已耗盡。計數依 UTC 日期，台灣時間每日 08:00 重設。

照片服務現在保留安全的後端錯誤代碼，畫面分別提示每日額度、用戶限流及連線失敗；未知錯誤仍顯示通用文字，不洩漏上游訊息。新增照片清單／圖片兩個階段遇到每日上限及重试恢復的 mock 測試，修正未提高上限或重設用量。
