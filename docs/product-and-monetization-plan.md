# 吃定了：UI／UX 與收費導入規格

更新：2026-09-19。這份文件區分本輪已完成的本機功能與後續產品規劃。金鑰與真實資料串接驗證依使用者要求留到最後；目前沒有收費、訂閱商品或會員權限系統。

## 產品定位

讓使用者快速決定一餐，再逐步減少不合適的推薦。先保住價格、地點與個人口味的可信度，再增加付費價值。

不以點擊「就吃這個」推定已用餐，也不把按「換一個」視為討厭某家店。價格等級僅代表相對消費水準，不能轉換成虛構的人均台幣金額。

## 本輪完成的操作流程

| 階段 | 操作與結果 |
| --- | --- |
| 第一次使用 | 歡迎頁可直接體驗，或回答三個口味問題；尚未啟動時不先要求定位 |
| 這餐 | 一家推薦、完整店名與理由、價格、評分／評論數、營業狀態；就吃／換店固定在底部 |
| 先看位置 | 「查看位置」開啟地址說明，可連到 Google Maps 或複製連結，不寫入確認紀錄 |
| 價格條件 | 省錢／日常／不限；飯店與價格未知開關各自獨立，保存後不扣換店次數 |
| 暫時略過 | 更多 → 這餐先跳過；同餐重開仍有效，下個餐段恢復，可一次還原 |
| 永久排除 | 不要這家／不要這類；從「我的」管理，與暫時略過分開 |
| 紀錄 | 最近決定／收藏；紀錄顯示尚未回報、吃過喜歡／普通／不合口味、沒有去吃 |
| 學習 | 僅實際吃過的紀錄影響嘗鮮與均衡提醒；喜歡提高分數，不合口味降低分數，不等於永久封鎖 |
| 我的 | 修改口味、價格、排除與定位；說明資料只存在本機 |
| 異常 | 保留已有推薦並提示重新整理失敗；地圖失敗可重試；新增收藏／回饋／略過先儲存成功才更新狀態 |

視覺沿用米色與暖棕色、Material 3；以留白和資訊層級改善判斷，不用不明來源的餐廳照片。Demo 明確標示；無實際定位不顯示公尺；關鍵內容可捲動並適應大字體。

## 下一版 UI 優先順序

1. 真實資料驗證後，補上「找不到符合價格的店」的原因統計，分辨價格未知、距離、飯店、休息與排除。保持原條件，讓使用者自己放寬。
2. 收藏支援指定為這餐與自訂清單；確認前刷新營業資訊，舊價格不要當成即時資訊。
3. 店家照片顯示基礎已接入，見 [照片功能](place-photos.md)；評論食物照篩選、真實照片驗證與菜單連結尚待完成。
4. 常用情境（例如上班午餐、晚餐約會、宵夜）保存價格、範圍與偏好，避免每次重選。
5. 群體決策先做小範圍原型，測試兩人排除條件如何合併；不要直接擴大成社交平台。

應用內嵌地圖目前未實作；現有流程是地址預覽加外開 Google Maps，可先完成找店與確認位置。

## 免費／付費功能分級（提案）

| 功能 | 免費版 | 未來 Plus |
| --- | --- | --- |
| 一餐一家、價格／飯店篩選、外部地圖 | 保留 | 同免費版 |
| 本機紀錄、收藏、用餐回饋、永久排除 | 保留 | 同免費版 |
| 每日換店 | 目前全 App 共 3 次 | 不把解除限制當唯一賣點；先觀察是否影響決定完成率 |
| 常用情境組合與行程規劃 | 基本條件 | 多組自訂情境、週間餐點安排（尚未開發） |
| 跨裝置備份與同步 | 本機使用 | 收藏、偏好、個人紀錄同步（尚未開發） |
| 雙人／群體決定 | 尚未開發 | 合併各自偏好與排除（先驗證需求） |

本機收藏等已開放功能不突然改成付費。暫時跳過與更改條件不扣配額，所以現有「每天換三次」不能當作可靠的付費權限或 API 成本控制。

### 成本連動的價格測試假設（2026-09-19 修訂）

原先 NT$69／月、NT$590／年暫不採用。新提案為 **NT$149 與 NT$199／月** 兩個價格測試點，年費暫緩；並非已上線售價或已確認的付費意願。需先降低重複請求，驗證每位用戶的成本與 Plus 的持續價值，再決定售價、用量和是否提供年繳。

以免費額度用完後的首階費率試算：每天約一次搜尋、每月 60 次詳情更新與 90 次照片載入，API 約 NT$92／人月。售價 NT$149，假設通路抽成 15%，扣 API 後只剩約 NT$34；NT$199 則剩約 NT$77，兩者都還沒付主機、稅、客服、退款、獲客和免費用戶成本。不能把餘額當成淨利，也不能因此認定 NT$199 一定有利潤。

完整假設、查詢數與計算見 [API 成本與訂閱方案](subscription-cost-plan.md)。這些數字不是商店即時售價；正式畫面必須讀取商店商品回傳的幣別與價格，不能寫死。功能尚未交付時不提供「立即訂閱」。

## 訂閱體驗與工程邊界（待實作）

- 入口：使用者主動開啟進階情境／同步時說明價值；首頁不強制付費牆。
- 付費頁：列出當前可用功能、期間、完整價格、自動續訂說明、恢復購買、管理訂閱、隱私與使用條款。保留清楚返回免費使用的入口。
- 購買狀態：載入商品、待付款、取消、失敗、交易驗證中、已開通；只有後端或可信交易驗證確認權益後才能開通。
- 權益狀態：免費、有效、取消但未到期、寬限期、暫停／到期、退款撤銷；取消續訂不立即剝奪已付期間。
- 本機可快取短期權益供離線顯示，但不能用 `shared_preferences` 的布林值作為付費依據。
- 後端負責訂閱驗證、通知冪等、到期／退款更新；支付憑證、API 私密金鑰不寫進客戶端。
- 同步需設計登入、資料合併、登出、本機保留選項、匯出與刪除帳號；這輪沒有新增帳號或雲端上傳。
- 測試需涵蓋沙盒首次購買、取消、失敗、恢復購買、換機、續訂、到期、退款與重複通知。通過後再啟用正式商品。

iOS 原則採 App Store 內購；Google Play 原則採 Play Billing，實際需按發行地區和適用例外確認。Apple 的自動續訂要求持續價值，應先交付服務再收費。參考：[Apple 內購與訂閱規範](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)、[Google Play 付款政策](https://support.google.com/googleplay/android-developer/answer/9858738?hl=zh-Hant)（查閱於 2026-09-18）。

## 成本與資料準備

- 同一批附近店家本機重算，換店、心情與預算調整不應各自發出一次 Nearby Search。
- 接入真實資料時記錄每次 API 成功／失敗與用量，再用實際 SKU 帳單估算每活躍用戶成本。不要假設一位使用者只查詢一次。
- 已完成 Places New 後端代理、金鑰隔離、每 IP 分鐘／日限額、全站每日上限與持久用量統計；尚未部署。匿名 IP 限流不等於會員／裝置驗證，供應商配額及告警等金鑰設定時處理。見 [後端說明](../server/README.md)。
- 真實收藏／歷史已改成持久保存 place ID 與個人回饋／時間，舊快照讀取時移除。詳情重新查價格／營業資訊，失敗保留紀錄並可重試；Demo 快照保留。Google 內容不作為永久自有餐廳資料庫。
- 真實資料顯示需補齊正式品牌歸因、必要作者資訊及公開條款／隱私頁；現有細字來源說明不應被視為已完成上架合規。參考：[Places 資料與歸因政策](https://developers.google.com/maps/documentation/places/web-service/policies)（查閱於 2026-09-18）。

## 導入順序與完成定義

1. **已完成**：本機核心流程與本輪 UI、價格／飯店篩選、收藏／回饋、測試和 iOS Demo 試跑。
2. **金鑰最後處理**：配置真實 Places，再實測定位、平價候選、飯店漏網與 Google Maps 對應。API mock 通過不能替代實地驗證。
3. **正式上線前**：部署已完成的後端與持久限額儲存、完成品牌歸因及必要的流量驗證、Android／iOS 實機驗證、隱私政策與簽署上架。
4. **收費開發前**：驗證 Plus 的使用需求與持續價值、定價、同步帳號方案。
5. **收費上線前**：實作並驗證購買／權益／恢復／退款全流程，最後設定正式商店商品與憑證。

完成本輪不等於正式訂閱已完成，也不等於真實餐廳資料已驗證。
